# 输入验证规范

## 基本原则

- 所有外部输入（请求参数、请求体、文件上传、HTTP 头、Cookie）默认不可信，必须先验证再使用。
- 优先使用白名单校验：明确允许的取值范围、类型、长度、格式；拒绝名单之外的任何输入。
- 校验应尽早进行，最好在进入业务逻辑之前完成（例如在 Web 框架的请求模型层）。

## 常见注入防护

- SQL 注入：严禁拼接用户输入构造 SQL 语句，必须使用参数化查询或 ORM。
- 命令注入：严禁将用户输入直接传入 shell 或 subprocess；如确需执行外部命令，使用参数列表形式并严格校验参数。
- 路径穿越：处理用户提供的文件名/路径时，必须规范化路径（如 resolve）并校验其位于允许的目录之内，拒绝包含 .. 的输入。
- XSS：将用户内容渲染到 HTML 时必须转义，优先使用框架自带的模板转义机制。

## 文件上传

- 必须限制上传文件的大小与数量。
- 不得仅凭客户端提交的 Content-Type 或文件扩展名判断文件类型。
- 上传文件应存储在非可执行目录，且不应直接暴露原始文件名。

## 反序列化

- 严禁对用户可控数据使用不安全的反序列化（如 Python 的 pickle、yaml.load 不带 SafeLoader）。
- 优先使用 JSON 等安全的数据交换格式，并用结构化模型（如 Pydantic）校验字段类型。
