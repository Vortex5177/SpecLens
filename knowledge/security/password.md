# 密码与凭据处理规范

## 密码存储

- 严禁以明文形式存储用户密码，严禁使用 MD5、SHA-1 等快速哈希算法直接哈希密码。
- 必须使用带盐的慢哈希算法存储密码，推荐 argon2（argon2-cffi 库）或 bcrypt（passlib 库）。
- 盐值必须为每个用户随机生成，不得多个用户共用同一盐值。
- 密码比对必须使用恒定时间比较函数，防止时序攻击。

## 密码强度

- 注册接口必须校验密码最小长度（建议不低于 8 位），并拒绝出现在常见弱密码字典中的密码。
- 不要在日志、异常信息、响应体中回显用户密码或任何凭据。

## 密钥与令牌

- API Key、数据库密码、JWT 签名密钥等机密信息严禁硬编码在源代码中，必须通过环境变量或密钥管理服务注入。
- .env 等包含机密信息的文件不得提交到版本库，不得发送给 LLM 或任何外部服务。
- JWT 必须设置合理的过期时间（exp 声明），签名算法必须显式指定（如 HS256/RS256），严禁允许 alg=none。
- 会话令牌应在用户登出、修改密码后立即失效。

## 错误信息

- 登录失败时不得提示"用户名不存在"或"密码错误"这类可区分的信息，应统一返回"用户名或密码错误"，防止用户名枚举。
