# 认证与授权规范

## 认证（身份识别）

- HTTP API 的认证凭据只应在 HTTPS 上传输；生产环境禁止使用 HTTP 明文传输密码或令牌。
- 推荐使用标准的认证方案（如 OAuth2 + Bearer Token、JWT），避免自造认证协议。
- 登录接口应有频率限制，防止暴力破解。
- 认证失败返回 401，权限不足返回 403，不要混用。

## 授权（权限控制）

- 每个接口都必须显式声明所需的权限要求，不得依赖"默认有权限"的假设。
- 授权检查必须在服务端完成，不能依赖前端隐藏按钮来控制访问。
- 注意水平越权：访问某个资源时必须校验当前用户是否有权访问该资源（例如用户 A 不能通过修改 URL 中的 ID 访问用户 B 的订单）。

## Web 框架实践（以 FastAPI 为例）

- 使用框架提供的依赖注入机制声明认证依赖（如 Depends），将认证逻辑集中在依赖中，而不是在每个路由里重复手写校验。
- 路由函数中需要当前用户身份时，应通过认证依赖注入获取，而不是自行解析请求头。

## 敏感操作

- 修改密码、删除数据、支付等敏感操作应要求二次确认或重新认证。
- 敏感操作的审计日志应记录操作人、时间、结果，但不得记录密码、令牌等机密内容。
